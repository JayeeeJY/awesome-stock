# 参与 Awesome Stock

Issue、想法和讨论都欢迎。代码改动也欢迎：先开一个 Issue 把问题和做法说清楚，再提交 Pull Request。这样可以避免花时间做了维护者暂时不会合并的改动。

## 在哪里聊

- 使用问题：[GitHub Discussions](https://github.com/JayeeeJY/awesome-stock/discussions)
- 缺陷和功能建议：[GitHub Issues](https://github.com/JayeeeJY/awesome-stock/issues)
- 安全问题：按 [SECURITY.md](SECURITY.md) 走 GitHub 私密漏洞报告，不要在公开 Issue 里贴利用细节

请用合成数据复现。不要附上 API Key、券商导出、真实持仓、研究底稿、数据库或备份。

## Pull Request

1. 先开 Issue，等维护者确认方向。
2. 改动尽量小，并写上你验证过什么。
3. 不要把密钥、个人账本或私人联系方式写进仓库。
4. 项目自有代码是 AGPL-3.0-only。提交即表示你同意按这个许可证贡献。本仓库不额外要求 CLA，也不要求把版权转给维护者。

本地检查见 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)。测试通过不等于已经批准合并、发版或改变许可。

维护者可能因为方向不合、范围太大，或还没准备好长期维护，请你改一改或暂时不合并。这不是拒绝交流。

# Contributing

Issues, ideas and discussions are welcome. Code changes are welcome too: open an issue, agree on the approach, then open a pull request.

## Where to talk

- Questions: [GitHub Discussions](https://github.com/JayeeeJY/awesome-stock/discussions)
- Bugs and feature requests: [GitHub Issues](https://github.com/JayeeeJY/awesome-stock/issues)
- Security: follow [SECURITY.md](SECURITY.md). Do not post exploit details in a public issue.

Reproduce with synthetic data. Do not attach API keys, brokerage exports, real holdings, private research, database files or backups.

## Pull requests

1. Open an issue and wait until the maintainer confirms the direction.
2. Keep the change focused, and say what you ran.
3. Do not commit secrets, a personal ledger, or private contact details.
4. Project-owned code is AGPL-3.0-only. A contribution is offered under that license. This repository does not add a CLA or a copyright assignment.

Local checks are described in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). Passing tests does not by itself approve a merge, a release or a license change.

The maintainer may ask for a smaller change, or may not merge yet, when the direction does not fit or the work is larger than they can maintain. That is not a refusal to talk.
